# Shopify Manage + Routing Merge, and Removing the Default Basket — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the admin-configured "default basket" fallback from Shopify basket routing (making routing fully explicit — manual pin or a matching rule, never a silent catch-all), and merge the merchant-facing Manage and Routing pages into one page with two tabs.

**Architecture:** Backend first — `funnel-resolution.ts` drops its final fallback tier and the `isDefault` column disappears from `shopify_funnel_templates`, which is a hard cutover (no backfill) that every downstream consumer (admin CRUD, 7 test files) must be updated to match. Frontend second — `RoutingPage`'s content becomes a tab rendered inside `ManagePage`, `/routing` becomes a redirect, and a new lightweight banner surfaces the pre-existing `unrouted` count wherever the merchant is on the page.

**Tech Stack:** Fastify 5 + zod, Drizzle ORM/drizzle-kit, Vitest (unit + integration, no testcontainers — reuses `pnpm docker:up`'s Postgres), React + Polaris (`apps/shopify`), plain React + hand-rolled components (`apps/admin-web`).

## Global Constraints

- Remove only the default-basket fallback; Aivastra's global condition-based rules (`shopify_funnel_rules` with `storeId IS NULL`) are untouched.
- Hard cutover, no backfill migration for stores currently relying on the default basket.
- Enforcement is "warn but allow" — no save-time gate blocking enablement of an unrouted product/collection.
- New precedence in `resolveBasketFrom`: manual pin → store's own rules → Aivastra global rules → `null` (refusal). No fourth tier.
- No production schema/data changes — `db:generate`/`db:migrate` run locally only (`pnpm docker:up` must be running), shipped to prod through push → CI/CD → `db:migrate:prod`, never by hand against `tryon_prod`.
- Merged page keeps both tabs' existing save models as-is: Eligibility stays staged behind `ContextualSaveBar`; Routing's rule CRUD and global-rule toggle stay immediate/unstaged.
- `/manage` is the canonical URL; `/routing` becomes a `<Navigate>` redirect, matching the existing `/products` → `/manage` and `/widget-design` → `/` redirects in `apps/shopify/src/App.tsx`.

- [ ] **Step 2: Remove the fallback tier from `resolveBasketFrom`**

Change the function's doc comment and body from:

```ts
/**
 * The ONE place basket precedence lives. Every caller — try-on creation, the
 * merchant product list, the Routing page counts — must go through this
 * function rather than re-deriving the rule, exactly as every activation
 * caller goes through computeEffectiveEnabled in activation.ts.
 *
 * Precedence: manual pin, then the store's own rules, then Aivastra global
 * rules, then the default basket. Null means nothing is configured at all,
 * which the try-on path treats as a refusal BEFORE deducting credits.
 */
export function resolveBasketFrom(
  ruleSet: BasketRuleSet,
  target: BasketMatchTarget,
): ResolvedBasket | null {
  // A pin to a basket an admin has since deactivated falls through rather than
  // refusing: dead-ending every pinned product with no merchant-visible cause
  // is worse than a visible downgrade to the rule-derived basket.
  const pinned = activeBasket(ruleSet, target.funnelTemplateId);
  if (pinned) return resolved(pinned, 'manual');

  // Store tier resolves entirely before the global tier — a store rule at
  // priority 100 still beats a global rule at priority 1. Interleaving the two
  // by priority would let a merchant's own rule silently lose to a global rule
  // whose priority they cannot see.
  for (const tier of [ruleSet.storeRules, ruleSet.globalRules]) {
    for (const rule of [...tier].sort(byPriorityThenId)) {
      const basket = activeBasket(ruleSet, rule.basketId);
      if (!basket) continue;
      // An empty condition list matches NOTHING, never everything: read the
      // other way, a half-filled rule form becomes a catalog-wide hijack.
      if (rule.conditions.some((c) => matchesCondition(c, target))) {
        return resolved(basket, 'rule');
      }
    }
  }

  const fallback = activeBasket(ruleSet, ruleSet.defaultBasketId);
  return fallback ? resolved(fallback, 'default') : null;
}
```
